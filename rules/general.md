# Общие правила работы

- Отвечать по-русски, включая итоговые сообщения. Идентификаторы в коде – как принято в проекте.
- Утверждения о поведении («встанет», «потеряется», «повторится») в ответах, рецептах и доках – только после
  чтения кода или теста, со ссылкой `file:line`. Не проверил – пометить «не проверял». README и ADR – не источник:
  их формулировки тоже сверять с кодом. Отдельно уточнять, о чем речь: обработка, коммит и чтение – разные вещи.
- Изменил поведение или API – найти тексты, которые это описывают (doc-комментарии, README, `docs/`, ADR),
  и обновить в том же диффе.
- Неактуальный комментарий, битую ссылку или устаревшее описание в файлах, с которыми работаешь, исправлять сразу,
  даже если это было до тебя, и коротко перечислять в отчете. Попутный рефакторинг по-прежнему нельзя.
- Не собирать руками то, что уже есть: перед своей конфигурацией, DI-регистрацией, фабрикой, валидацией, ретраем,
  метриками или хелпером найти готовое во фреймворке, стандартных библиотеках и общих библиотеках проекта
  и использовать его. Свой примитив – только если готовое не подходит, с комментарием почему. На ревью искать
  такие дубли так же, как баги.
- Перед созданием или правкой README и `docs/**/*.md` прочитать `~/.claude/rules/docs-readme.md`, если оно еще
  не в контексте.
- Пока идут долгие задачи (фоновые команды, сборки, тесты, установки, субагенты), присылать пользователю апдейт
  каждые 3 минуты. В апдейте сначала – что пошло не по плану и как из-за этого поменялся курс, если поменялся;
  потом – что сейчас происходит и сколько примерно осталось. Для этого заводить Monitor или проверки по таймеру
  и не останавливать их, пока задачи не закончились.
- Экономить контекст: все загруженное перечитывается на каждом следующем шаге до конца чата.
  - Справку по Claude Code (настройки, хуки, флаги) спрашивать у агента claude-code-guide – он возвращает только
    ответ. Скилл update-config ради одного поля не загружать: его схема настроек – около 100 тыс. токенов.
  - Вывод команд ограничивать сразу: фильтр, `Select-Object -First N`, только размеры. Папку с неизвестным
    числом файлов целиком не листать.
- Ссылки в ответах всегда рабочие, в один клик. Упомянутый файл – ссылкой, а не путем в `коде`. Файл внутри папок
  сессии – относительная ссылка; все остальное (worktree, соседние репозитории) – веб-ссылка на GitLab или GitHub
  по полному SHA коммита, который есть на сервере. Перед отправкой открыть хотя бы по одной ссылке каждого вида.
